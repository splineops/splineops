# Resize benchmark evidence

The dated subdirectories retain complete, machine-readable benchmark bundles
generated by `scripts/benchmark_resize_pr.py`. They are development-machine
snapshots, not portable performance guarantees.

## 2026-07-17 oblique-PR profile

`2026-07-17-oblique-pr/` was generated from commit `7d1f7a4` with:

```shell
python scripts/benchmark_resize_pr.py \
  --profile oblique-pr \
  --output-dir benchmarks/resize/2026-07-17-oblique-pr \
  --tag oblique_pr_20260717_7d1f7a4
```

The environment was Linux 6.17, Python 3.12.3, NumPy 2.4.6, SciPy 1.17.1,
scikit-image 0.26.0, OpenCV 4.13.0, and PyTorch 2.12.0+cpu. The generated
manifest, commands, CSV, JSON, and Markdown report are retained together.

The main results were:

- Native versus Python fallback: 46 overlaps, median 53.63x acceleration.
- Oblique antialiasing native versus Python: 13 overlaps, median 47.42x.
- Exact-ish SciPy comparisons: SciPy faster in 0/16 rows.
- Contextual OpenCV comparisons: OpenCV faster in 18/18 rows; these rows have
  different grids, filters, boundaries, or dtype behavior.
- Equal-degree projection comparison: degree-1 oblique was faster in 0/36
  rows with a 0.82x median ratio; degree-3 oblique was faster in 32/36 rows
  with a 1.20x median ratio.

The last result supersedes the pre-v2 handoff's timing claim that oblique was
faster in every degree-1 and degree-3 row. The v2 direct compact cross-Gram
pipeline materially changed the equal-degree reference cost. Oblique remains
the public antialiasing preset family, but a current performance claim must be
degree- and workload-specific.

This evidence does not revive or approve the historical upstream PR package.
Any upstream use still requires human technical ownership and appropriate
AI-assisted-development disclosure.
